# MyFirstPlugin — Dome PvP (Work in Progress)

A custom Minecraft Java Edition minigame plugin for **Paper 26.3**, developed with Java and Gradle. The long-term goal is a Battle Royale / “Under the Dome” PvP arena with a shrinking safe zone and a minimap HUD.

> **Development status:** This is a prototype, not a finished Battle Royale product. Existing example commands such as `/heal` and `/gethammer` work only if their Java classes are present in the compiled JAR. The planned **live Dome-zone overlay on NMinimap is not implemented yet**. The `/dome` commands are available only after the corresponding `DomeCommand` is added and registered.

## 1. Requirements

| Component | Version / role | Required? |
| --- | --- | --- |
| [Paper](https://papermc.io/downloads/paper) | **26.3** Minecraft server | Yes |
| Java | **25 or newer** for Paper 26.3; Java 26 can be used for development | Yes |
| Minecraft: Java Edition | Client version **26.3** (unless a version-compatibility proxy/plugin is configured) | Yes |
| [NMinimap](https://hangar.papermc.io/NezuShin/NMinimap) | 1.0.9 or a compatible release; minimap HUD | For the minimap |
| [AnvilORM](https://github.com/NezuShin/AnvilORM/releases) | **1.0.2 or newer**; NMinimap dependency | With NMinimap |
| [PacketEvents](https://modrinth.com/plugin/packetevents) | Spigot/Paper build (tested setup: **2.14.0**) | With NMinimap |
| [LuckPerms](https://luckperms.net/) | Permission management (local test: Bukkit 5.5.91) | Optional |
| spark | Performance profiling; may already be provided by Paper | Optional |
| bStats | Statistics data folder created by plugins | **Not a separate dependency** |

The basic commands do not need NMinimap; the minimap features do. This setup targets **Paper**, not a Forge or Fabric modded client. NMinimap works without a client-side mod, but each player must have its **resource pack** applied.

## 2. Set up a Paper server

1. Install **Java 25+** and verify with `java -version`.
2. Download the **Paper 26.3** server JAR from [PaperMC](https://papermc.io/downloads/paper).
3. Place it in a dedicated server folder and rename it to `paper.jar`.
4. Start the server from that folder:

   ```powershell
   java -Xms1G -Xmx2G -jar paper.jar --nogui
   ```

5. Read the Minecraft EULA and, if you agree, change `eula=false` to `eula=true` in the generated `eula.txt`.
6. Start the server again and verify it reports `Done (...)!`.
7. To connect from the same computer, open **Minecraft Java Edition → Multiplayer → Direct Connection → `localhost`**. The default server port is `25565`.

If using a managed host, select Paper 26.3 and Java 25+ in the hosting panel instead.

## 3. Install the plugins

Stop the server before copying or replacing JAR files. Put all plugin JARs **directly** in the server's `plugins/` folder, not inside its subfolders.

Example directory:

```text
paper-server/
├── paper.jar
├── eula.txt
├── server.properties
├── plugins/
│   ├── MyFirstPlugin-1.0-SNAPSHOT.jar
│   ├── NMinimap.jar
│   ├── AnvilORM.jar
│   ├── packetevents-spigot-2.14.0.jar
│   ├── LuckPerms-Bukkit-5.5.91.jar   # optional
│   ├── NMinimap/                  # generated after launch
│   ├── LuckPerms/                 # generated if installed
│   ├── spark/                     # may be generated by profiler
│   └── bStats/                    # automatically generated statistics data
└── logs/
```

File names can differ depending on the downloaded version. **Do not copy the Paper server JAR into `plugins/`**: it runs the server itself.

1. Install **AnvilORM** and **PacketEvents**.
2. Install **NMinimap**.
3. Add the compiled **MyFirstPlugin** JAR.
4. Optionally install LuckPerms for fine-grained permissions.
5. Restart Paper and use `/plugins` and `logs/latest.log` to confirm successful loading.

Download third-party plugins from their official project pages; respect their respective licenses.

## 4. NMinimap: hide other players

For a Battle Royale game, we do not want the minimap to reveal where other players are.

Open:

```text
plugins/NMinimap/config.yml
```

In the **existing** `markers:` section, change this value (do not create a second `markers:` block):

```yaml
markers:
  player-marker: "player"          # keep own position
  another-players-marker: ""       # hide other players
```

Save and reload as an operator:

```text
/minimap admin reload
```

Helpful player commands:

```text
/minimap enable
/minimap side right
/minimap style square
/minimap scale 4
/minimap radar disable
```

If you do not want mob radar available at all, configure the existing `markers.mob-radar.enable` setting in NMinimap's config as `false`.

> **For buyers:** This NMinimap setting is not stored in MyFirstPlugin's ignored `run/` folder. Each new server must apply it, unless a supported integration automates it in a future version.

## 5. NMinimap resource pack (required on every player's client)

NMinimap generates its resource pack after installation. The default output is:

```text
plugins/NMinimap/built-pack.zip
```

**Local testing:** Apply this ZIP as a Minecraft Java Edition resource pack on your test client.

**For a public server:** Host the ZIP at a publicly accessible **direct HTTPS download URL**, then configure `server.properties`:

```properties
resource-pack=https://example.com/built-pack.zip
require-resource-pack=true
resource-pack-sha1=REPLACE_WITH_THE_ACTUAL_SHA1_OF_YOUR_ZIP
```

Replace the example URL and SHA-1 string before starting the server. On Windows PowerShell, calculate the SHA-1 of the pack from your server directory:

```powershell
(Get-FileHash -Algorithm SHA1 .\plugins\NMinimap\built-pack.zip).Hash
```

Players are prompted to download/apply the pack on joining. With `require-resource-pack=true`, players who refuse or cannot load it are disconnected. **No client-side mod is required.** Re-upload the ZIP and update its SHA-1 whenever the generated resource pack changes.

If the server already uses a resource pack, consider a compatible **resource-pack merger/manager** instead of replacing the existing pack.

## 6. Commands and permissions

Commands depend on which classes have actually been compiled and registered in the current JAR:

| Command | Function | Status |
| --- | --- | --- |
| `/heal` | Heal the executing player | Example implementation in this project |
| `/gethammer` | Give a custom named iron axe (“Thors Hammer”) | Example implementation in this project |
| Right-click with the magic item | Custom lightning effect | Requires an implemented and registered `MagicWandListener` |
| `/dome start` | Start shrinking world-border match | Planned prototype; requires `DomeCommand` |
| `/dome join` | Join the PvP arena | Planned prototype; requires `DomeCommand` |
| `/dome stop` | Stop the match/reset the border | Planned prototype; requires `DomeCommand` |

Known permission nodes from the example configuration:

- `meinplugin.hammer` — access to `/gethammer`, if declared as a command permission in `plugin.yml`.
- `myfirstplugin.dome.admin` — proposed admin permission for `/dome start` and `/dome stop`, once implemented (suggested default: `op`).
- `nminimap.admin` — NMinimap admin commands.

If LuckPerms is installed, permissions can be granted as needed. Example (replace the username):

```text
/lp user PlayerName permission set meinplugin.hammer true
```

Server console commands do not need the leading slash.

## 7. Development in IntelliJ IDEA

This repository was set up using **Minecraft Development → Plugin → Paper**, Java, Gradle, and Minecraft 26.3. Development uses JDK 26; when distributing to Java 25 servers, compile with `options.release.set(25)` and verify the resulting JAR on Java 25.

For a checked-in Gradle wrapper on Windows, run from the **project root**:

```powershell
.\gradlew.bat build
.\gradlew.bat runServer
```

Alternatively, run `build` / `runServer` in IntelliJ's Gradle tool window. `runServer` creates a **local test server** under `run/` (unless configured differently). Stop that server before replacing plugin JAR files.

Example repository layout:

```text
MyFirstPlugin/
├── src/main/java/me/example/myFirstPlugin/
├── src/main/resources/plugin.yml
├── build.gradle.kts
├── settings.gradle.kts
├── gradle/wrapper/
├── gradlew
├── gradlew.bat
├── README.md
├── .gitignore
├── build/       # generated; ignored
└── run/         # local test server; ignored
```

Recommended `.gitignore`:

```gitignore
.gradle/
build/
run/
.idea/
```

Keep `gradlew`, `gradlew.bat`, and the wrapper configuration **tracked** for reproducible builds. Do not publish local server worlds, log files, generated packs, or third-party JARs as if they were your own code.

## 8. Dome PvP roadmap (not yet a completed feature)

The intended game design is:

1. A separate world called `pvp_arena`.
2. A `WorldBorder` starting at **400 × 400 blocks**.
3. The safe zone shrinks gradually to **20 × 20 blocks**, e.g. over 10 minutes.
4. Players take damage when outside the safe zone.
5. NMinimap shows the player's position, while enemy-player markers are disabled.
6. **To implement:** Draw the *current and upcoming* safe-zone boundaries on each player's minimap HUD.
7. **To implement:** Lobby, random spawns, multiple shrink phases, eliminations, spectator mode, winner detection, configuration and restart handling.

The ordinary NMinimap does **not** automatically draw this custom Dome safe-zone rectangle. That requires additional code/integration with its rendering API. Do not advertise this feature to buyers as finished until it is implemented and tested.

## 9. Troubleshooting

- **Plugin missing from `/plugins`:** Ensure the JAR is directly in `plugins/`, is built for your Paper version, and check `logs/latest.log`.
- **`Unknown command`:** Check `plugin.yml`, command registration and that you restarted with the newest MyFirstPlugin JAR.
- **`No permission`:** Grant the relevant permission using OP/LuckPerms, or check `plugin.yml`.
- **Minimap invisible:** Confirm NMinimap, AnvilORM and PacketEvents loaded; make sure the generated resource pack is applied on the client.
- **Other players visible on minimap:** Set `markers.another-players-marker: ""` in NMinimap's configuration and reload.
- **`runServer` exits immediately:** Check the EULA and the generated `run/logs/latest.log`.
- **Cannot connect to `localhost`:** The server must be running and listening on port `25565`; check `server.properties` and the console.
